OVERVIEW                                                    *novelist-overview*

`novelist` is a small, dependency-free Neovim plugin for prose writers. It
combines prose-friendly buffer settings with a lightweight revision cockpit for
Markdown and plain-text drafts.

It provides automatic local prose options for supported buffers,
heading-based section navigation, current-section and document word counts,
configurable standalone story/revision markers such as `@who:` and `@todo:`, a
document map outline of headings and Markdown structure, an opt-in suggested
keymap preset, and an optional explicit `:NovelistVale` check that runs a
user-installed Vale.

`novelist` does not infer story meaning automatically. It does not bundle
grammar or style checking, but you can run an external, user-installed Vale
over the current buffer with `:NovelistVale`. It installs named commands only;
it does not create default keymaps unless you opt in to the suggested preset.

==============================================================================
REQUIREMENTS AND INSTALLATION                                *novelist-install*

Requirements:

- Neovim 0.12+ is the release target.
- No required third-party Neovim plugins or external tools.
- Optional: Vale (https://vale.sh) for |:NovelistVale|. You install and
  configure Vale yourself; `novelist` neither installs it nor requires it.

Install the repository with your preferred Neovim plugin manager, using the
manager's normal syntax for a plugin repository. In generic terms: >lua

  -- Add the novelist repository with your plugin manager.
  -- Then configure it after the plugin is on 'runtimepath':
  require('novelist').setup()
<

The runtime plugin calls `require('novelist').setup()` with defaults when it
loads. Calling `setup()` yourself is safe and updates the active configuration.

The dependency-free test suite can run under the available local Neovim runtime,
but passing it on an older runtime does not replace the required manual Neovim
0.12+ smoke test for release validation.

==============================================================================
SETUP AND CONFIGURATION                                      *novelist-setup*

Default configuration: >lua

  require('novelist').setup({
    prose = {
      enabled = true,
      filetypes = { 'markdown', 'text' },
      spell = true,
      spelllang = { 'en_us' },
      wrap = true,
      linebreak = true,
      breakindent = true,
      textwidth = 0,
    },
    markers = {},
    vale = { executable = 'vale' },
    keymaps = { preset = false, mappings = {} },
  })
<

Supported filetypes are `markdown` and `text` by default.

Keymaps are configured with `keymaps`; plain `setup()` installs none. See
|novelist-keymaps|.

Prose options:

                                                        *novelist-prose-options*
`prose.enabled`                                      Default: `true`
        Apply prose settings on supported |FileType| events.

`prose.filetypes`                       Default: `{ 'markdown', 'text' }`
        Filetypes that receive the prose preset. Replaces the default list when
        configured.

`prose.spell`                                        Default: `true`
        Local spell checking value.

`prose.spelllang`                         Default: `{ 'en_us' }`
        Local spell language list. Tables are applied as comma-separated spell
        languages.

`prose.wrap`                                         Default: `true`
        Visual wrapping.

`prose.linebreak`                                    Default: `true`
        Break wrapped lines at convenient characters when possible.

`prose.breakindent`                                  Default: `true`
        Preserve indentation visually on wrapped lines.

`prose.textwidth`                                    Default: `0`
        Do not insert hard wraps into saved text.

Disable automatic prose settings globally: >lua

  require('novelist').setup({
    prose = { enabled = false },
  })
<

Disable automatic prose settings for one buffer before its |FileType| event
applies: >lua

  vim.b.novelist_disable = true
<

Markers are configured with `markers`. Entries override the default marker
descriptions, new names add enabled markers, and `false` disables a marker.
Marker descriptions are for user-facing text only; marker values in buffers
remain arbitrary text. >lua

  require('novelist').setup({
    markers = {
      who = 'POV first, then other characters present.',
      thread = 'Revision thread or subplot note.',
      todo = false, -- disable the default @todo marker
    },
  })
<

`vale` options:

                                                        *novelist-vale-options*
`vale.executable`                                    Default: `'vale'`
        Vale executable name or path used by |:NovelistVale|. There is no
        `vale.enabled` option: checking only happens when you invoke
        |:NovelistVale|.

Set the executable: >lua

  require('novelist').setup({
    vale = { executable = '/usr/local/bin/vale' },
  })
<

==============================================================================
COMMANDS                                                  *novelist-commands*

                                                        *:NovelistSceneNext*
:NovelistSceneNext
        Move to the next Markdown ATX section heading. Warns if there is no
        next heading.

                                                        *:NovelistScenePrev*
:NovelistScenePrev
        Move to the previous Markdown ATX section heading. Warns if there is no
        previous heading.

                                                        *:NovelistWordCount*
:NovelistWordCount
        Report current section words and document words with |vim.notify()|.

                                                        *:NovelistMarkers*
:NovelistMarkers [name]
        Put matching marker lines in the quickfix list. Optional [name] filters
        by marker name, such as `todo`. Opens the quickfix window only when
        matches exist.

                                                        *:NovelistDocumentMap*
:NovelistDocumentMap
        Open a navigable outline of the current buffer in a vertical split
        while keeping the source visible.

                                                        *:NovelistVale*
:NovelistVale
        Check the current Markdown or plain-text buffer with a user-installed
        Vale and show findings in the invoking window's location list.

Sections are based on Markdown ATX headings (`#` through `######` followed by
whitespace). A headingless document is treated as one implicit whole-document
section for word counts; heading navigation reports that no section heading
exists.

==============================================================================
DOCUMENT MAP                                           *novelist-document-map*

:NovelistDocumentMap opens a navigable outline of the current buffer in a
vertical split while keeping the source visible. The outline uses a dedicated
scratch buffer; re-running the command rebuilds it, and there is no live edit
tracking.

Outline rows show indentation for nesting, a concise label, and the source line
number in brackets. Listed elements are:

- headings (`#` through `######`) as a hierarchy;
- fenced code blocks, list items, blockquotes, and tables when Markdown
  Tree-sitter parsing succeeds for the buffer;
- configured standalone marker lines, found with the same line parser used by
  |:NovelistMarkers|, whether or not Tree-sitter is available.

Put the cursor on a row and press Enter (`<CR>`) to switch to the source buffer
and jump to its source line. If the source buffer no longer exists, the jump is
skipped with a warning. Running `:NovelistDocumentMap` from the outline itself
warns instead of nesting another split.

`novelist` does not install or configure Tree-sitter or any parser. If the
Tree-sitter API or a Markdown parser is unavailable, or parsing fails, the
outline falls back to headings plus markers and shows a notice that richer
Markdown structure is unavailable. Installing a Markdown parser is optional and
owned by you.

==============================================================================
VALE (OPTIONAL)                                                *novelist-vale*

:NovelistVale runs Vale (https://vale.sh), an external grammar and style
checker, over the current buffer. Vale is optional and user-owned: you install
it and provide your own Vale configuration and styles. `novelist` does not
install Vale, write `.vale.ini` or styles, or require Vale for any other
feature.

The command checks the current buffer's contents, including unsaved edits, and
runs asynchronously so Neovim stays responsive. It supports `markdown` and
`text` buffers; other filetypes are rejected with a warning. Named buffers are
checked with their file path; unnamed buffers are checked as Markdown or plain
text according to their filetype.

Findings are placed in the invoking window's location list, which opens only
when there is at least one finding. The global quickfix list is never modified.
When there are no findings, `novelist` reports that instead of opening an empty
list.

If Vale cannot be launched, exits with an unexpected error, or returns output
that cannot be parsed, `novelist` reports the error and leaves the window's
existing location list untouched. If the invoking window has closed or no
longer shows the checked buffer by the time the asynchronous check finishes,
the results are not shown anywhere and `novelist` reports that they could not
be displayed.

Checking is always explicit: `novelist` does not lint while you type, add
autocmds, or create a keymap for the command.

Set the executable used by |:NovelistVale| with `vale.executable` (default
`'vale'`). See |novelist-vale-options|.

==============================================================================
KEYMAPS                                                    *novelist-keymaps*

`novelist` installs no keymaps by default. Opt in to the suggested preset
explicitly: >lua

  require('novelist').setup({
    keymaps = { preset = 'suggested' },
  })
<

The suggested preset installs global Normal-mode mappings:

`scene_next`      `<leader>nn`      |:NovelistSceneNext|
`scene_prev`      `<leader>np`      |:NovelistScenePrev|
`word_count`      `<leader>nw`      |:NovelistWordCount|
`markers`         `<leader>nm`      |:NovelistMarkers|
`document_map`    `<leader>no`      |:NovelistDocumentMap|

Customize each action with `lhs` (key), `mode` (a single mode string, default
`n`), and `desc` (description), or disable one action with `false`: >lua

  require('novelist').setup({
    keymaps = {
      preset = 'suggested',
      mappings = {
        scene_prev = { lhs = '<leader>nb' }, -- move one key
        word_count = { mode = 'i', desc = 'count words' },
        markers = false, -- keep <leader>nm free
      },
    },
  })
<

Existing user or other-plugin mappings are never overwritten: a conflicting
suggested key is skipped and reported with a warning, while the other actions
still install. Calling `setup()` again updates or removes only mappings Novelist
installed, so repeated configuration does not duplicate maps and unrelated
mappings are left alone.

==============================================================================
MARKERS                                                    *novelist-markers*

Markers are standalone Markdown/plain-text metadata lines: >text

  @name: value
<

The marker line may have leading whitespace. Names may contain word characters,
`_`, and `-`. Only enabled marker names are recognized; unknown or disabled
marker names are ignored. Inline `@` mentions are not parsed.

Default markers:

`@who`     Viewpoint character first, followed by other important people in the
           scene. Example: `@who: Mira (POV), Ivo`

`@what`    Central event, conflict, or change in the scene. Example:
           `@what: Mira discovers the forged letter`

`@where`   Scene location. Example: `@where: North bridge, east tower`

`@when`    Placement in the story chronology. Example:
           `@when: Winter, year 12`

`@why`     Why the scene matters: its purpose, stakes, or cause in the story.
           Example: `@why: Forces Mira to choose whether to trust Ivo`

`@todo`    Unresolved drafting/revision task; may appear anywhere and repeat.
           Example: `@todo: Seed the letter's wax seal earlier`

`@why` means scene purpose or stakes by default. You may write character
motivation there when useful, but `novelist` treats the value as plain
writer-authored text.

==============================================================================
WORD-COUNT LIMITATIONS                                  *novelist-word-count*

Word counts are intentionally simple:

- counts are whitespace-delimited non-empty tokens;
- recognized standalone marker lines are excluded;
- section heading text is counted after stripping the leading Markdown heading
  prefix;
- other Markdown syntax is not parsed, normalized, or removed;
- sections are heading boundaries only, not inferred chapters or scenes.

MANUAL SMOKE TEST                                      *novelist-smoke-test*

Manual validation on Neovim 0.12+ remains a release gate unless it is actually
run on that runtime.

1. Install or add this repository to 'runtimepath' with your plugin manager.
2. Start Neovim 0.12+ and run `:checkhealth` or `:version` to confirm the
   runtime version.
3. Open a Markdown buffer and set `:set filetype=markdown` if needed.
4. Confirm prose settings with: >vim

     :setlocal spell? spelllang? wrap? linebreak? breakindent? textwidth?
<
5. Add sample content: >markdown

     # Opening
     @who: Mira (POV), Ivo
     Mira finds the forged letter.
     @todo: Seed the wax seal earlier

     ## Turn
     Ivo denies everything.
<
6. Run `:NovelistWordCount` and confirm it reports section and document counts.
7. Run `:NovelistSceneNext` and `:NovelistScenePrev` from different lines and
   confirm cursor movement between headings.
8. Run `:NovelistMarkers` and `:NovelistMarkers todo`; confirm matching lines
   appear in quickfix and filtering works.
9. Optionally set `vim.b.novelist_disable = true` before applying a supported
   filetype in a new buffer and confirm prose settings are skipped.
10. Run `:NovelistDocumentMap` in a Markdown buffer with a Markdown Tree-sitter
    parser installed (parser setup is yours and optional) and confirm the
    outline opens in a vertical split beside the source with heading hierarchy,
    the richer Markdown rows, and source line numbers.
11. Move through the outline with Enter on several rows and confirm the cursor
    lands on the matching source line; edit the source, confirm the outline is
    unchanged until re-run, then re-run `:NovelistDocumentMap` and confirm it
    refreshes.
12. Repeat the document-map check in a plain-text buffer or with no Markdown
    parser available and confirm the headings-only outline opens with the
    reduced-structure notice.
13. Optionally configure `keymaps = { preset = 'suggested' }` and confirm the
    five `<leader>n?` mappings, then check one `lhs`/`mode`/`desc` override and
    one `false` disable; confirm plain `setup()` leaves those keys unmapped.
14. Install Vale and create your own Vale project (a `.vale.ini` and styles) in
    a scratch directory. Vale configuration is yours; `novelist` neither
    creates nor changes it.
15. Open a Markdown draft from that project, add a sentence Vale will flag, and
    run `:NovelistVale`. Confirm the invoking window's location list opens with
    the finding, and confirm the global quickfix list (`:copen`) is unchanged.
16. Edit the buffer without saving and run `:NovelistVale` again; confirm the
    findings reflect the unsaved text.
17. Run `:NovelistVale` in a buffer with no findings and confirm `novelist`
    reports that there are no findings instead of opening an empty location
    list.

Automated checks:

Run the dependency-free headless suite: >sh

  ./tests/run.sh
<

Help documentation should resolve from the plugin runtime path after help tags
are generated: >sh

  nvim --headless -u NONE --cmd 'set rtp^=.' -c 'helptags doc' -c 'help novelist' -c 'quitall'
<

If that command creates `doc/tags` during validation, remove it before
committing unless the release process explicitly wants generated help tags
tracked.
