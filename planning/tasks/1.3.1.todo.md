# 3.1 — Public setup, settings lifecycle, and commands

## Goal
Connect the existing `novelist.settings` and `novelist.cockpit` modules behind a repeatable public `require('novelist').setup(opts)` entry point, adding runtime initialization, settings lifecycle autocmds, user commands, and integration coverage without changing the core modules or installing default mappings.

## Notes
- Use `settings.apply` as the only settings mutation point and keep lifecycle registration owned by integration.
- Use cockpit functions over buffer lines for all heading, count, and marker behavior; do not duplicate parsing logic in command code beyond adapting UI inputs/outputs.
- Repeated setup should update the active configuration while reusing or replacing registrations idempotently, never accumulating duplicate autocmds or command definitions.
- Default marker handling should preserve Task 2.2 semantics: default markers are enabled unless overridden, and entries set to `false` are disabled.
- The local automated runtime remains Neovim 0.11.6; target-version 0.12+ smoke validation is outside this task.
