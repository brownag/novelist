# 2.2.1 — Scratch outline UI and document-map command

## Goal
Register `:NovelistDocumentMap` through the existing `commands.register` lifecycle, build outline entries from the current source buffer and active marker configuration via `document_map.build`, and display them in a dedicated scratch buffer in a vertical split that keeps the source visible. Rows render nested structure (indentation from `depth`), concise labels, and source line numbers; each real row is mapped to its originating buffer/line. `<CR>` on a valid row switches to the source buffer/window and jumps to the source line. Re-invocation regenerates the outline with no live edit tracking, reduced Markdown structure is indicated, and empty documents / stale source buffers never raise.

## Notes
- Scope boundary (approved): edit only `lua/novelist/commands.lua`; leave `lua/novelist/init.lua` unchanged because `M.setup` already calls `require('novelist.commands').register(M.get_config)`, which is the lifecycle the new command joins; create only `tests/unit/document_map_integration_test.lua`. No README/help, no new dependency, no quickfix use, and no default global keymaps (the only keymap is buffer-local to the plugin-owned outline buffer, permitted by the skill and task).
- Model contract from Task 2.1.1: `document_map.build(lines, opts)` -> `{ entries, rich, reason }`; entries are a flat line-sorted list carrying `kind`/`label`/`line`/`depth`/`raw` (+ `level` on headings, `marker`/`value` on markers). Tree-sitter rows are already 1-based in `line`; `depth` drives indentation.
- Approved judgment calls: readable `<indent><label>  [<line>]` rows with visible non-jumpable notice/placeholder header rows (rather than transient `vim.notify`); and reuse of one named scratch outline buffer (`novelist://document-map`, `bufhidden=wipe`) so re-running refreshes instead of stacking splits, recreating it if wiped.
- No edit/`TextChanged` autocmd is registered, so the outline is intentionally stale until the command is re-run.
- Runtime facts verified locally before writing this plan: `vim.fn.bufnr('novelist://document-map')` resolves a named scratch buffer; a `vsplit` yields `winlayout()[1] == 'row'` with the source still visible; `nvim_feedkeys('<CR>', 'x', false)` triggers a buffer-local mapping under `--headless`; `vim.treesitter.get_string_parser` is present on this runtime.
- The rich-path integration test is guarded by a parser probe because Tree-sitter availability is environment-dependent; the fallback tests always run.
