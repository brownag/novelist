# 3.2.1 — Explicit command and location-list integration

## Goal
Wire the UI-free `novelist.vale` adapter into an explicit `:NovelistVale` command that lints the
invoking markdown/text buffer's current (unsaved) contents asynchronously and shows findings only
in that window's location list, never touching the global quickfix list.

## Notes
- Adapter contract (3.1.1): `vale.check({ executable, lines, path?, ext? }, cb)`; `cb` gets
  `{ ok = true, diagnostics, code, stdout, stderr }` or `{ ok = false, error, code?, stdout?, stderr? }`;
  diagnostics are `{ path, line, col, end_col, severity, message, check, match }` with 1-based line and
  1-based `col`/`end_col` (already quickfix-ready). Exit 1 = findings is handled inside the adapter, so
  `ok = true` with diagnostics is not an error.
- Capture winid/bufnr/lines/name before launch; run all editor API calls after `vim.schedule` because
  the real adapter's callback runs in `vim.system`'s fast event context. Tests stub `vale.process` and
  call the callback synchronously, so tests must pump scheduled work with `vim.wait(ms, predicate)`.
- Location lists are window-local; use `setloclist(winid, …)` and `getloclist(winid)`. Never call
  `setqflist`/`copen`. Open a foreign window's list with `nvim_win_call` so the user's current window
  is restored. Both closure and buffer-switch cases must hit the same "window no longer displays the
  captured buffer" guard, so no unrelated loclist is written.
- Style: match `list_markers` (qflist item shape, `notify` prefixes, `current_buffer`/`current_lines`
  reuse); `vim.cmd('lclose')` in test cleanup since `helpers.with_buffer` only closes quickfix.
- Observed during execution: closing a location-list window with `lclose` keeps the window's loclist
  contents, and test windows are reused across cases. `with_loclist_cleanup` therefore clears every
  window's loclist at test start so `#getloclist(winid)` predicates only reflect the current run.
