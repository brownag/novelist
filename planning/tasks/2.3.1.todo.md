# 2.3.1 — Opt-in suggested mapping preset

## Goal
Add a single opt-in `suggested` mapping preset that installs five global Normal-mode
mappings (`<leader>nn/np/nw/nm/no`) for the four existing commands plus
`:NovelistDocumentMap`, with per-action `lhs`/`mode`/`desc` overrides and `false` to
disable. Installation lives in a new `lua/novelist/keymaps.lua` and is reconciled on
every `setup()` so repeated configuration updates/removes only Novelist-owned maps,
pre-existing user/other-plugin maps are never overwritten (skipped and reported), and
plain `setup()` / plugin load still installs no keymaps.

## Notes
- Scope boundary: edit only `lua/novelist/init.lua`; create only
  `lua/novelist/keymaps.lua` and `tests/unit/keymaps_test.lua`. No changes to
  `commands.lua`, `cockpit.lua`, `document_map.lua`, `settings.lua`, `README.md`,
  `doc/novelist.txt`, or existing tests.
- Config shape: `keymaps = { preset = 'suggested', mappings = { <action> = false | {
  lhs =, mode =, desc = } } }`; default `{ preset = false, mappings = {} }`. Action IDs:
  `scene_next`, `scene_prev`, `word_count`, `markers`, `document_map`.
- Approved decisions: (a) module API `keymaps.setup(config)` invoked from `M.setup`;
  (b) ownership tracked in a module-local registry keyed by action with deletes gated by a
  `maparg` `rhs`+`desc` match; (c) conflicts WARN via `vim.notify(..., WARN)` and skipped;
  (d) `mode` treated as a single mode string passed through to
  `vim.keymap.set`/`maparg`; (e) unknown action IDs in `mappings` are ignored; (f) RHS uses
  `<cmd>NovelistX<cr>` command strings rather than Lua callbacks.
- Runtime facts verified locally (Neovim 0.12.5, `-u NONE`): `maparg` expands `<leader>`
  at call time; `vim.keymap.del(mode, '<leader>nx')` deletes the resolved map and returns
  `false` without error when absent; `vim.keymap.set` silently overrides, so conflict
  detection must run before install; `nvim_get_keymap` returns global maps only, so the
  buffer-local `<CR>` map from 2.2.1 does not interfere.
- `maparg(lhs, mode, false, true)` returns a normalized `rhs` (e.g.
  `<Cmd>NovelistSceneNext<CR>`) plus `desc`/`lhs`, which is the ownership signature stored
  after each install.
- No default maps: default `preset = false` keeps plain `setup()` and
  `plugin/novelist.lua` map-free, satisfying the existing `setup installs no default
  keymaps` test.
- Test isolation: the harness runs all test files in one Neovim process; the owner
  registry persists across `require_fresh_novelist` (only `novelist` is cleared), so
  `clear_all()` and a final `{ preset = false }` teardown keep later files
  (`settings_test`) unaffected.
- Baseline re-confirmed during analysis: `git status` clean; current suite is
  `34 passed, 0 failed`.
