# 2.1.1 — Document structure model with optional Tree-sitter

## Goal
Create `lua/novelist/document_map.lua`, a rendering-independent outline model that always yields Markdown ATX headings plus configured markers and, when Markdown Tree-sitter parsing succeeds, adds fenced code blocks, list items, blockquotes, and tables, falling back to the existing line-based `cockpit.headings` outline on missing parser or parse failure.

## Notes
- Scope is only `lua/novelist/document_map.lua` and `tests/unit/document_map_test.lua`; no edits to `cockpit.lua`, `init.lua`, `commands.lua`, settings, docs, existing tests, or `plugin/`.
- Judgment call (the plan review delegates this to the worker): the outline is a flat, line-ordered entry list; nesting is expressed by `depth` (and `level` for headings). Container nodes are not emitted, which keeps rows deterministic and duplicate-free.
- `depth` is uniform for the future renderer: headings use their ATX level, list items use list nesting depth, and code/quote/table/marker entries use `1`.
- Tree-sitter node types verified against the Neovim 0.12.5 runtime grammar: `atx_heading` (+ `atx_h1_marker`…`atx_h6_marker`, `inline`), `fenced_code_block` (+ `info_string`), `list`/`list_item`, `block_quote`, `pipe_table` (+ `pipe_table_cell`).
- ADR 0001 separation honored: `M.build` only consumes `lines` + an injectable tree and returns data; no window/buffer/command code here.
- Constraints honored: no parser install/config, no new dependency, no inline syntax, no change to `cockpit` parsing semantics; markers always come from `cockpit.find_markers`, so marker support never depends on Tree-sitter.
- Risk: Tree-sitter ranges are 0-based rows, so add `+1` for parity with `cockpit.headings` line numbers; all parser interaction is wrapped in `pcall` since parser absence is expected, not an error.
- Baseline re-confirmed during analysis: `git status` shows only the three untracked planning docs, and `make test` reports `22 passed, 0 failed`.
