## Notes
- Only implementation/test files in scope are `lua/novelist/vale.lua` and `tests/unit/vale_test.lua`; this microplan is the permitted planning artifact. Do not modify command/UI integration or README/vimdoc, add dependencies, or leave temp fixtures in the repository.
- `vale.build_argv()` currently adds `'-'` after `--output=JSON`, optional `--ext=...`, and optional `--path=...`. The adapter passes `table.concat(lines, '\n')` to `vim.system` stdin asynchronously and accepts exit codes 0/1 before parsing JSON.
- Task 3.3.1 evidence in `planning/STATE_3.md`: Vale 3.20.0 with temp user-owned configuration found a repetition from stdin when `--path` was supplied without a positional argument, but returned `{}`/exit 0 with trailing `-`; headless `:NovelistVale` consequently showed no finding and quickfix was empty.
- Adapter tests currently inject `vale.process` for deterministic results; extend that style to verify exact argv and findings parsing without depending on real Vale. Real configured smoke is separately required by acceptance.
- Preserve existing user config discovery, diagnostic JSON parsing, async execution, findings exit-code classification, and failure behavior. ADR 0001 keeps this optional dependency isolated from Neovim UI integration; ADR 0002 retains explicit named-command behavior and no default mappings.
- No unresolved implementation/API question identified during analysis.
- Implementation evidence: `./tests/run.sh` reported `Tests: 49 passed, 0 failed`. Real smoke used Vale 3.20.0 and Neovim 0.12.5 with a temporary `/tmp` project containing `.vale.ini` and a custom `Test.Repetition` style. Running headless Neovim from that project cwd with unsaved `This is is unsaved text.` yielded one `Repeated word` diagnostic in the invoking window's `Novelist Vale` loclist; clean text yielded an empty loclist and `novelist: no Vale findings`; a pre-populated global quickfix (title `Preserved quickfix`, one `keep quickfix` item) remained unchanged both times. An initial attempt ran Neovim from the repository cwd and timed out because Vale did not discover the temporary config; rerunning with the configured project as cwd passed.
