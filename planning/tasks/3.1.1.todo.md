# 3.1.1 — Vale process and diagnostic adapter

## Goal
Build a small, dependency-free, UI-free adapter in `lua/novelist/vale.lua` that asynchronously
runs Vale over the current buffer text (including unsaved edits) via stdin, parses Vale's JSON
diagnostics into stable records, and reports results through a completion callback while cleanly
separating findings from launch/process/parse errors.

## Notes
- Verified Vale JSON schema and exit codes with a controlled local invocation (controlled facts,
  not assumptions): findings output is a JSON object keyed by the input path → array of alerts
  `{ Action, Span = { startCol, endCol }, Check, Description, Link, Message, Severity, Match, Line }`
  with `Line` and `Span` 1-based; **exit 1 = findings**, **exit 0 = `{}` no findings**,
  **exit 2 = internal/config error** emitted as a single error object `{ Line, Path, Text, Code, Span }`.
- Neovim runtime doc facts (read from `runtime/doc/lua.txt`): `vim.system()` **throws if `{cmd}`
  cannot be run** (so launch failure is caught with `pcall`); `opts.stdin` accepts a `string`
  (“written to stdin and closed”); `opts.text = true` returns stdout/stderr as text;
  `vim.json.decode` exists and decodes `{}` to `vim.empty_dict()`.
- Scope (approved): create only `lua/novelist/vale.lua` and `tests/unit/vale_test.lua`, plus the
  task/state planning files. Do not edit `commands.lua`, `init.lua`, README/help, or existing tests;
  no dependencies, no config/styles, no synchronous invocation, no UI calls.
- Deterministic process seam (spec-permitted alternative to a temp fake executable) is used so the
  tests never require an installed Vale or `.vale.ini` and stay platform-independent; the seam also
  captures argv/stdin to prove `--ext`/`--path` context and unsaved-text stdin.
- Adapter contract consumed by 3.2.1: `vale.check({ executable, lines, path, ext }, on_done)` with
  `on_done` receiving either `{ ok = true, diagnostics, code, stdout, stderr }` or
  `{ ok = false, error, code?, stdout?, stderr? }`; the integration task owns loclist/notify/async
  scheduling and the default executable.
- Risk recorded for manual smoke: an ad-hoc local probe of `/usr/bin/vale` 3.20.0 returned `{}`
  for piped stdin while identical text in a file produced findings (possibly a probe/config-discovery
  quirk). The adapter still passes buffer text via stdin per the approved plan; this should be
  confirmed against a real user-configured Vale during the 3.3.1 manual smoke gate, not claimed now.
